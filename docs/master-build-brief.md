# ATTIRA — Master Build Brief
### One platform. Every life domain. Built to go deep.

> **What this document is:** the complete plan to build Attira as a single website/app covering every module, with the depth that makes it irreplaceable. Hand this to Claude Code as your `CLAUDE.md`, and use it yourself as the product bible.

---

## PART 0 — The single most important idea

You want every module to be so detailed that people need nothing else. There are two ways to attempt this, and only one of them works.

**The way that fails:** hand-write the content for every module. Every skincare rule, every interview question, every English lesson, every budgeting tip. This takes years, and the result is *still* shallow, because static content can never respond to one specific person's situation.

**The way that works:**

| Layer | What it is | Why it creates depth |
|---|---|---|
| **1. Memory Engine** | One shared brain. Every module writes what it learns; every module reads everything. | The app knows you across domains. Your interview coach knows you're nervous before presentations. Your stylist knows you have a wedding Friday. This is the moat. |
| **2. Module Framework** | Every domain has the same skeleton: **Assess → Profile → Plan → Track → Coach**. | You build the skeleton once. Each new domain is configuration, not a rebuild. Fifteen domains stop being fifteen projects. |
| **3. Knowledge Scaffolds** | Per domain, you author the *rules and guardrails* (ingredient logic, styling logic, ATS rules, safety limits) — not the answers. | The model generates infinitely detailed, personalised guidance *within* your scaffold. This is how you "cover anything" without writing everything. |

**Everything below is an expression of these three layers.** Build them properly and the app can absorb any new life domain forever without a rewrite.

### One site, many domains

```
├──────────────────────────────────────────────────────────┤
│  COMPANION  — proactive nudges · daily brief · check-in   │
├──────────────────────────────────────────────────────────┤
│  MEMORY ENGINE  ◄── the heart. all modules read/write     │
├──────────────────────────────────────────────────────────┤
│  MODULE REGISTRY  — every domain plugs in here            │
│                                                           │
│  Appearance │ Growth │ Career │ English │ Dating          │
│  Wellness   │ Finance│ Learning│ Comms  │ Home & Life     │
└──────────────────────────────────────────────────────────┘
```

### The module contract (every domain implements this)

```ts
interface Module {
  id: string;                 // 'style' | 'skin' | 'career' | 'english' ...
  name: string;
  icon: string;
  tier: 'free' | 'premium' | 'plus';

  assess(): Question[];       // the intake quiz
  profile(answers): Profile;  // structured result → written to memory
  plan(profile): Plan;        // 30/60/90 or per-domain roadmap
  track(): Metric[];          // what progress looks like here
  coach(context): Prompt;     // domain system prompt + knowledge scaffold
  score(): number;            // 0-100, feeds the Life Score
}
```

Because every module is the same shape:
- The dashboard renders any module automatically.
- The Life Score aggregates automatically.
- Streaks, XP and reports work automatically.
- **Adding "Finance" later = writing one config file. Not a rewrite.**

## PART 2 — The Memory Engine (build this FIRST)

This is the product. Everything else is a surface on top of it.

### Three tiers of memory

| Tier | What | Example |
|---|---|---|
| **Facts** | Stable attributes | skin type: combination · height: petite · undertone: warm · budget: mid |
| **Episodes** | Timestamped events | "Interview at HDFC on 12 Aug" · "Started retinol 1 Sep" · "Felt low after presentation" |
| **Patterns** | Derived insights | "Skips routine on weekends" · "Confidence dips before public speaking" · "Responds well to short wins" |

Facts are cheap to store and retrieve. Episodes give the app a timeline. **Patterns are what make it feel uncanny** — they're generated by a nightly job that reads recent episodes and writes conclusions.

### Retrieval (how a module gets context)

Don't dump the whole memory into every prompt — it's expensive and noisy. Instead:

1. Always inject **core facts** (small, ~200 tokens).
2. Inject the **active module's profile**.
3. Semantically retrieve the **top 5–10 relevant episodes/patterns** for this query (vector search).
4. Inject **recent conversation**.

### Privacy — non-negotiable, and a selling point

- Ask before storing anything sensitive (health, relationships, finances).
- A **Memory page** where the user can view, edit, export and delete anything. Full stop.
- Sensitive categories encrypted at rest.
- Never train on user data. Say so, loudly — it's a differentiator.

## PART 4 — The modules (all of them, in depth)

Every module = **Assess → Profile → Plan → Track → Coach**. Each has a *knowledge scaffold*: the rules you author, inside which the model generates unlimited personalised detail.

### 1. APPEARANCE OS *(your wedge — build deepest first)*

**1a. Style & Wardrobe**
- Assess: shape, height, skin depth, undertone, face shape, style persona, coverage preference, comfort (Western/ethnic/fusion), fit, climate, budget, profession.
- Profile: colour palette + colours to avoid, metals, necklines/collars, silhouettes, fabrics, prints, footwear, accessories, eyewear, hairstyles.
- Deep features: **virtual wardrobe** (upload clothes → auto-categorise → generate outfits), capsule wardrobe builder, occasion outfits (office/wedding/date/gym/party/traditional/travel), packing lists, shopping lists, outfit comparison, seasonal refresh.
- **Knowledge scaffold:** colour-season theory, body-proportion rules, occasion dress codes, Indian ethnic wear logic.

**1b. Skin**
- Assess: type, concerns (acne, pigmentation, pores, dullness, texture, redness, dark circles, fine lines, dehydration, sun damage), lifestyle (sleep/water/diet/stress), allergies, current products, climate, budget.
- Profile: skin type, concern ranking, sensitivity flags.
- Deep features: AM/PM/weekly routines with correct **layering order**, **ingredient-list analyser** (paste or photo → what each does, flags irritants, finds redundancy, compares two products), conflict warnings (retinoid + strong acid), patch-test prompts, **progress photo timeline with before/after**, monthly skin score, product expiry & shelf-life tracker, seasonal and travel routine adjustments, SPF/water reminders.
- **Knowledge scaffold:** the ingredient matrix — for each of ~25 actives: what it does, which concerns, who it suits, side effects, pairs well with, use with caution with, frequency, AM/PM, time to visible results.
- **Guardrails:** ingredients not brands (brands optional, as *examples* by region/budget, never endorsements). Cosmetic, never medical. Refer to a dermatologist for persistent/severe issues. Retinoid warnings for pregnancy.

**1c. Hair & Scalp**
- Concerns: hair fall, thinning, dandruff, dry/oily scalp, frizz, breakage, heat damage, coloured-hair care, greying, curly/straight/wavy/coily care.
- Outputs: wash-day + daily routine, ingredient recommendations with evidence level, cut and colour suggestions matched to face shape, styling ideas.
- **Also:** beard care, eyebrow grooming.

**1d. Beauty extras** — makeup (matched to colouring and face), fragrance, nails, dental, body care.

### 2. PERSONAL GROWTH
Daily coaching · journaling · gratitude · vision board · morning routine · evening review · goal planner · habit tracker · mindset · stress · focus · time management · decision frameworks · personal mission statement · monthly reflection · yearly planning.
**Scaffold:** habit-formation science (cue-routine-reward), goal frameworks (OKR/SMART), CBT-style reframing prompts.

### 3. CAREER
Resume builder + **ATS scoring** · LinkedIn optimiser · portfolio review · job matching · **interview simulator (text + voice)** · mock interviews with feedback · salary negotiation · promotion roadmap · career switching · skill-gap analysis · leadership & workplace communication · conflict resolution · presentation coaching · networking messages · professional emails · freelancing & startup roadmaps.
**Scaffold:** ATS parsing rules, STAR method, negotiation frameworks, role competency maps.

### 4. ENGLISH
Level assessment (CEFR) · speaking practice · **pronunciation & accent analysis (voice)** · listening · reading + comprehension · vocabulary + daily words with spaced repetition · grammar correction · business/interview English · email writing · conversation simulations · role-play · public speaking · story reading · daily challenges · writing feedback · IELTS/TOEFL prep.
**Scaffold:** CEFR level descriptors, spaced-repetition scheduling, error-type taxonomy.

### 5. DATING & RELATIONSHIPS
Profile & bio guidance · dating-app optimisation · conversation coaching · first-date prep · date planner · gift recommendations · anniversary/birthday reminders · communication analysis · **green flags education & red flag awareness** · difficult-conversation practice · breakup recovery · marriage prep.
**Guardrail:** guidance and confidence — **never attractiveness scoring of people's faces.**

### 6. WELLNESS
Walking plans · water · sleep · movement & home workouts · gym plans · stretching · posture · meditation · stress reduction · healthy recipes · meal planning.
**Guardrail:** healthy habits, **not** medical diagnosis. Body-positive: no weight targets, no calorie restriction, no diet prescriptions.

### 7. FINANCE
Budgeting · expense & subscription tracking · savings goals · emergency fund · EMI tracking · net worth · financial habit coaching · investment *education*.
**Guardrail:** education, explicitly **not** financial advice.

### 8. LEARNING
AI tutor · book summaries · flashcards (spaced repetition) · revision planner · learning roadmaps · skill tracking.

### 9. COMMUNICATION
Public speaking · debate · storytelling · negotiation · difficult conversations · leadership comms · **speech analysis (voice)**.

### 10. HOME & LIFE
Shopping lists · meal planning · travel planning · packing lists · home organisation · cleaning schedules · gift planner · festival planner · pet & plant care reminders.

### CROSS-CUTTING: THE COMPANION
- **Daily Brief** each morning: priorities, habits, one challenge, mood check, a nudge from whichever module needs attention.
- **Daily Check-in** each evening: mood, stress, sleep, energy, gratitude, journal.
- **Proactive nudges** (the magic): *"Your interview is tomorrow — want to run a mock?"* · *"You haven't practised English in 5 days."* · *"Three weeks of routine consistency. That's when skin starts showing it."*
- **Weekly / monthly / yearly reports** — progress, patterns, next steps.
- Fully user-controlled. Thoughtful, never nagging.

## PART 5 — AI routing (quality where it counts, cheap where it doesn't)

| Task | Model tier | Why |
|---|---|---|
| Deep coaching, resume rewrite, interview feedback, complex reasoning | **Frontier (Opus-class)** | Quality is the product |
| Everyday chat, routine generation, module Q&A | **Mid (Sonnet-class)** | The workhorse — best cost/quality |
| Classification, tagging, summarising, embeddings | **Fast (Haiku-class)** | Cheap, high volume |
| Nightly pattern extraction | **Fast/Mid, batched** | Runs offline, batch pricing |

**Cost control:** cache the system prompts and knowledge scaffolds (they're identical across users), retrieve *selectively* from memory rather than dumping it, batch the nightly jobs, and stream responses so it *feels* instant.

> **⚠️ Superseded — do not use an old palette.** The design has moved on from an earlier violet/blue/teal direction. The current, approved design is:
> 1. **The imported Claude Design handoff** (screens 1a–1g, 2a–2d) — this is the **primary visual source of truth**. Build pixel-faithful to it.

>
> If this file and the imported design ever disagree, **the imported design wins.**

**Summary of the current direction** (see `/design/design-system.md` for full detail):
- **Palette:** warm ivory + lavender as the signature theme (with a sage/periwinkle "fresher" alternate — confirm which ships as default), and a distinct deep-aubergine **dark "ceremony" mode** reserved for night rituals and real milestones — not just a generic dark theme.
- **Type:** an elegant warm serif for headlines/hero numbers (scores, streak counts) + a clean humanist sans for UI/body text. Small-caps, wide-tracked eyebrow labels throughout.
- **Motion:** spring easing, animated ring fills, swipe-to-complete gestures, morphing card expand/collapse. Confetti/full-bleed celebration **reserved for real milestones only** — never on ordinary days. Respect `prefers-reduced-motion`.
- **Signature components:** progress rings (score, streak, check-in indicators) · streak tracker with a visible "freeze" safety net · ritual step cards ("NOW" tag, swipe-to-complete) · day-complete ceremony card · knowledge/library collection cards · 30-day journey path · drag-to-compare progress timeline.
- **Every screen needs:** empty state (illustration + one action, never "No data") · loading state · error state. Accessible (WCAG AA, keyboard nav, screen-reader labels, reduced-motion).

## PART 7 — Gamification (without the pressure)

XP per meaningful action · levels · daily streaks per module · badges · weekly challenges · monthly missions · **Life Score** (the aggregate of every module score) · skill trees · unlockable themes · transformation timeline.

**The ethical line:** reward consistency, never punish absence. No guilt-tripping copy. Streaks get a "freeze" so one missed day doesn't destroy months of effort — that's what turns a streak from stressful into supportive.

## PART 9 — Build sequence with Claude Code

**Claude Code** is Anthropic's agentic coding tool — it reads your codebase, edits files, runs commands. It works in the terminal, your IDE, the desktop app, and the web, and it's **included in the Pro and Max plans**. So you likely already have it.

### The stack (chosen for a solo builder)
- **Next.js + TypeScript + Tailwind** — one codebase, web + mobile-responsive
- **Supabase** — Postgres + auth + file storage + vector search, all in one, generous free tier
- **Anthropic API** — the intelligence layer
- **Vercel** — deploy, free tier, custom domain
- **Stripe / Razorpay** — subscriptions (Razorpay for India)

### The order — do NOT skip or reorder
| Phase | Build | Why here |
|---|---|---|
| **1** | Auth + database + shell + design system | Nothing works without the foundation |
| **2** | **Memory Engine** | *Everything* depends on it. Build it before any module. |
| **3** | **Module framework** (the contract in Part 1) | Build once, then modules are cheap |
| **4** | Style module (deep) — proves the framework | If the framework can carry Style, it can carry anything |
| **5** | Skin module (deep) + photo upload + progress timeline | Your strongest retention feature |
| **6** | Hair, beauty extras | Completes the Appearance OS → **this is your launchable product** |
| **7** | Companion: daily brief, check-in, nudges, streaks | Turns it from a tool into a habit |
| **8** | Career, English, Dating, Growth | Now each is a config file, not a project |
| **9** | Wellness, Finance, Learning, Comms, Home | Same |
| **10** | Gamification polish, reports, referrals, billing | Monetize and grow |

**Ship after Phase 6.** Get real users on the Appearance OS while you build the rest. Feedback beats guessing, and revenue beats waiting.

### How to actually drive Claude Code
1. Install it (terminal, IDE, or desktop — see `docs.claude.com/en/docs/claude-code/overview`).
2. Create the project folder. **Put this document in it as `CLAUDE.md`** — Claude Code reads it at the start of every session, so it always knows the architecture and the guardrails.
3. Work **one phase at a time**, in plain English. Example first prompt:

> *"Read CLAUDE.md. Set up a Next.js + TypeScript + Tailwind project with Supabase auth and the database schema in Part 3. Then build the app shell — landing page, onboarding flow, and dashboard — matching the imported Claude Design handoff as the primary visual source, cross-checked against /design/design-system.md if anything is ambiguous. 4. Then: *"Now build the Memory Engine from Part 2 — facts, episodes, patterns, the retrieval function, and the Memory settings page where users can view, edit, export and delete."*

## PART 10 — The things that will make or break this

**What actually creates the moat** (in order):
1. **Memory that compounds.** Not features. Memory.
2. **Visible progress.** Before/after photos, scores climbing, streaks. People stay for evidence that they're changing.
3. **The companion feeling proactive but not needy.** Get this wrong and they mute you. Get it right and they open it daily.

**The three ways this fails:**
- **Spreading thin.** Fifteen shallow modules beat by fifteen specialists. → *Antidote: go deep on Appearance first, ship it, then expand.*
- **Building for two years without users.** → *Antidote: ship after Phase 6.*
- **Feature-chasing instead of memory-building.** → *Antidote: Phase 2 exists for a reason.*

**Non-negotiable guardrails** (build these into every prompt):
- Never say "AI" to the customer. The brand speaks: *"curated for you."*
- Skincare = ingredients, cosmetic, never medical. Refer out for real conditions.
- Wellness = habits, never diagnosis. **No weight targets, no diets, no calorie policing. Dress to shape.**
- Finance = education, never advice.
- Dating = confidence and guidance, **never scoring people's attractiveness.**
- Memory = ask before storing sensitive things; always let people delete.
